## 2026-05-22 — User corrections to draft v1 (round 1)

Three corrections applied; supersede any prior phrasing in brief.md and any conflicting language in the brainstorm/TSCT reference.

1. **DigiLocker KYC is OPTIONAL at v1 launch.** Becomes mandatory only once DigiLocker provider approval is granted. Until then, KYC fields are captured manually and validated by trustees. Implication for PRD/architecture: KYC data shape must be source-agnostic (manual OR DigiLocker can populate the same fields); a feature flag flips the enforcement from optional to mandatory without schema work.
   - Updated: Executive Summary / The Solution (core loop step 1), Scope > In.

2. **Screenshot upload retained as optional fallback, not killed.** Primary reconciliation path is UTR self-attestation + nominee-pushed bank statement. Screenshot upload becomes **mandatory only when the self-attested UTR fails to match** the nominee's statement — giving the member a clear path to resolve the mismatch. This preserves TSCT-style proof-of-payment for the edge cases while removing it from the routine flow.
   - Updated: The Solution (core loop step 4), What Makes This Different (reconciliation bullet), Scope > In (UPI/reconciliation line).

3. **Payment gateway is NOT permanently off-limits — it's scoped.** Correction to overstated "Ever" in prior draft. Payment gateway is **out for the support-pool flow forever** (member → nominee stays UPI Intent direct), but **enters the product when the Crowdfunding Module ships in Phase 2/3**, scoped strictly to public-donor → trust → nominee flows with 80G receipts. The earlier wording risked locking out a Phase-2/3 capability that is already in the roadmap.
   - Updated: What Makes This Different (no-gateway bullet).
