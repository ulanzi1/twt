## Story

As Solo Builder,
I want a schema-diff CI gate enforcing that v1 ships **no** `payout_destinations` table, column, endpoint, validator, Zod schema, or UI surface,
so that Durghatana Sahayata (Accident Assistance) activation at v2/v3 must be a **greenfield addition** (new table + new endpoints + new module) rather than a column/index add to v1 tables — discharging the FR-100 forward-compat-hooks non-add discipline (architecture §1.13 Hook 2) from day one across every intermediate epic.

## Acceptance Criteria

> **Read first — three things this story is NOT, and one word that misleads.** (1) The name says **"schema-diff,"** but the realization is an **invariant forbidden-pattern scan of the current repo state**, NOT a git-diff against a PR base ref. The "diff against the v1 baseline" framing (epics L1338, architecture L1158) means *"the v1 baseline permits **zero** payout-destination artifacts; assert zero exist"* — a full static scan of current state is both correct and strictly more robust than a base-ref diff (a diff could miss an artifact added earlier on the branch, or wrongly pass one already merged). ⇒ **NO `fetch-depth: 0`** — mirror sibling 1.16b (`pii-scrape`, current-state scan), do **NOT** cargo-cult sibling 1.16a (`friction-budget`, which needs `fetch-depth: 0` only because its declaration facet genuinely diffs the base ref). (2) It is **NOT** the OpenAPI breaking-change semantic-diff gate (D1-1.4) — that is a *different* gate (semantic-diff of `openapi/v1.yaml` for breaking changes) loosely co-routed to "1.16c" in deferred-work; it is orthogonal to FR-100 non-add and stays deferred (AC-6). (3) It is **NOT** a fold-in to the existing `db:check` job — `db:check` is `drizzle-kit check` (a canned drizzle command that cannot host custom asserts), and the gate is **repo-global** (it scans migrations **and** `apps/api` endpoints **and** `packages/contracts` Zod). So it lands as a new repo-root `scripts/schema-diff/` gate (the home 1.16b's Dev Notes already predicted for the c/d siblings), and the stale `db-check` comment that names 1.16c is reconciled (AC-4).

### AC-2 — Four precision-scoped forbidden-pattern scanners (pure, fixture-tested)
**Given** the pattern registry (AC-1) + the four artifact domains the epics AC enumerates (epics L1338) + architecture §1.13 Hook 2 ("No `payout_destinations` table; no `payout_destination_id` column on `members`/`claims`/`pools`/`payments` or any v1 entity; no API endpoint, Zod schema, validator, OpenAPI route, or UI surface", L1153-1157)
**When** the gate scans the repo
**Then** it runs **four scanners**, each over a **precisely-scoped artifact root** (see Dev Notes → *Scan roots*):
  - **(a) Tables** — over the latest `packages/domain/migrations/meta/*_snapshot.json` (the authoritative cumulative drizzle schema; enumerate `tables` keys) **and** all `packages/domain/migrations/*.sql` (raw DDL belt-and-suspenders) → any table named `payout_destinations` is a finding.
  - **(b) Columns** — same source → any column whose name matches `payout_destination*` (on any table) is a finding.
  - **(c) Endpoints** — over `apps/api/src/**/*.ts` route path **string literals** → any path matching `/payout-destinations*` is a finding.
  - **(d) Zod schemas** — over `packages/contracts/src/**/*.ts` **exported identifiers** → any export name matching `*PayoutDestination*` is a finding.
**And** any finding **fails CI** with a **clear pointer to the offending artifact** (epics L1339): the finding names the kind (table/column/endpoint/zod), the matched artifact, the file (+ line/migration where available), and the pattern it violated — structured `findings[]` accumulation + per-finding print, mirroring `friction-budget`'s `failures[]` posture.
**And** all scanner logic is **pure + importable** (takes already-read file contents / parsed JSON, returns `Finding[]`) and **fixture-unit-tested**: each scanner gets a **positive** fixture (a forbidden artifact → finding, asserting the named pointer) **and** a **negative** fixture (a compliant artifact → no finding); plus malformed-config → throw.

- [x] [Review][Patch] `loadLatestSnapshot` silently swallows JSON parse errors — `catch` block returns `null` (treats a corrupt snapshot as "not found"), causing all snapshot-based table/column checks to be skipped and the gate to silently pass on the snapshot side; should rethrow or `process.exit(1)` with a clear error. [`scripts/schema-diff/check.ts:loadLatestSnapshot`]
- [x] [Review][Patch] `scanColumns` table-name skip is case-sensitive but `tokenRe` is case-insensitive — `if (token === tableName) continue` fails for uppercase SQL tokens (e.g. `PAYOUT_DESTINATIONS` from hand-written migrations), emitting a spurious `column` finding for the table name; fix: `token.toLowerCase() === tableName`. [`scripts/schema-diff/lib.ts:scanColumns`]
- [x] [Review][Defer] `scanEndpoints` scans all string literals, not just route-registration call sites — error messages, log strings, or test fixtures in `apps/api/src/**/*.ts` mentioning `/payout-destinations` could trigger false positives; v1 risk is zero (gate is green by construction today). [`scripts/schema-diff/lib.ts:scanEndpoints`] — deferred, pre-existing
- [x] [Review][Defer] `scanZodSchemas` misses `export default` and re-export forms (`export { X } from`, `export * as N from`) — underlying named `export const` definitions are caught at their source file; re-exports are rare in contracts packages; `export default` is non-idiomatic in `packages/contracts`. [`scripts/schema-diff/lib.ts:scanZodSchemas`] — deferred, pre-existing

### CRITICAL — "schema-diff" is an INVARIANT SCAN, not a git-diff (the #1 mechanism reconciliation)
The story name and the epics phrase "compares every PR's Drizzle migration set against the v1 baseline" (L1338) sound like a base-ref diff. They are **not**. The v1 baseline permits **zero** payout-destination artifacts *ever* — so the correct, robust realization is: **scan the current repo state and assert zero FR-100 artifacts exist.** A base-ref git-diff would be strictly worse here: it could (a) miss a forbidden artifact introduced earlier on the same branch, and (b) wrongly pass a forbidden artifact already merged to `main`. A whole-state invariant scan has neither failure mode. ⇒ **NO `fetch-depth: 0`**, no `GITHUB_BASE_REF`, no merge-base — mirror sibling `pii-scrape` (which also scans current state), NOT sibling `friction-budget` (whose `fetch-depth: 0` exists *only* for its declaration facet's genuine base-ref diff). Cargo-culting `fetch-depth: 0` here would be the exact anti-pattern 1.16b's Dev Notes warned about in reverse.

### CRITICAL — precision-scoping IS the self-green invariant (the #2 reconciliation)
The four FR-100 keywords (`payout_destinations`, `payout_destination`, `/payout-destinations`, `PayoutDestination`) are **everywhere** in non-artifact files: the epics (L1331-1344, L3522, L4304-4312), the architecture (§1.13, §4.15), the PRD (§4.15 FR-100), `deferred-work.md` (D9-1.2, W11), `sprint-status.yaml` (1.16b ledger comments mention `payout_destinations`), package READMEs, and this story file. **None of those are artifacts.** If the gate's globs are sloppy (e.g. "scan all `*.yaml`" or "scan the repo root" or "scan `*.md`"), it red-fails its own introducing PR on documentary mentions. The scanners MUST be scoped to **exactly** the four artifact roots and MUST exclude: `_bmad-output/**`, `docs/**`, every `**/*.md`, `sprint-status.yaml`, the gate's own `scripts/schema-diff/**` (fixtures contain the strings), and `fr-100-non-add.yaml` (the config lists the patterns). Self-green is *designed in via scope*, not luck.

### Mechanism — DECIDED: repo-root `scripts/schema-diff/`, NOT a turbo task and NOT a `db:check` fold-in
**This is settled by ground truth, not an open fork** (Decision 1 below is a confirmation, not a choice):
- The gate is **repo-global** — its four assertions span `packages/domain` (tables/columns), `apps/api` (endpoints), **and** `packages/contracts` (Zod). No single workspace owns all four, so a per-package turbo task can't express it. → repo-root `scripts/`, exactly like `friction-budget`.
- `db:check` is **`drizzle-kit check`** — a canned drizzle migration-consistency command. It **cannot** host custom forbidden-pattern asserts. So the `db-check` ci.yml comment that says "Story 1.16c commits the substantive v1-baseline forbidden-pattern asserts" was aspirational; reconcile it to point at the new `schema-diff` job (AC-4). The disjoint ownership (deferred-work D9-1.2: "Architecture-committed disjoint ownership") is honored: `db:check` keeps the lightweight drift primitive; `schema-diff` owns the substantive FR-100 asserts.
- Root scripts `schema:check` (`tsx scripts/schema-diff/check.ts`) + `schema:test` (`vitest run scripts/schema-diff`). `scripts/` is not a workspace → not in `turbo test` → the CI job runs `schema:test` explicitly (the `friction-budget` precedent). No `turbo.json` change.
