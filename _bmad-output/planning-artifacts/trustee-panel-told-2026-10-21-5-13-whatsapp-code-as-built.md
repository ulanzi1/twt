## What we are building

A member who ticks the WhatsApp box while signing up, on a phone that does not have their WhatsApp, can tap *"WhatsApp on another
phone?"* and ask for a code. The Trust sends a 6-digit code by WhatsApp to the member's registered number. The member reads it on the
phone that has their WhatsApp and types it into the app, and WhatsApp messages are switched on — recorded exactly like a yes given by
the member's own WhatsApp message. If it does not work, the member can still send the short message from that other phone, or carry on
signing up without WhatsApp.

## Five things you should know

**1. "One retry" is built as one more code, and two tries at each code.** A member can ask for the code once, and once more if it does
not arrive — at most two codes for one request. Each code can be typed in twice (a second try after a mistake). Your option as put said
*"one code per request"*, and its cost said the Trust messages someone *"once, at their request"*; with the retry, it is at most twice.

**2. What counts as a code sent.** If WhatsApp refuses a code for the member's number, it still counts as one of the two. If the
message never left our side, if WhatsApp asked us to wait, or if WhatsApp refused it because of a problem with the Trust's own account,
it does not count — the member can ask again. So WhatsApp may be asked more than twice, but at most two codes can reach the member.

**3. A STOP sent before the code is typed.** If a member replies STOP to the code message, nothing is switched on — there is nothing to
switch off yet. If they later type the code into the app anyway, WhatsApp is switched on: we treat the member's last act as their
answer. They can also still ask for the second code. A STOP after WhatsApp is on works as always.

**4. Only while signing up.** The code is offered only on the signup screen, and the server also refuses a member who has already
finished signing up. One wording point: the app's words say the code is sent to *"your WhatsApp number"*; it is in fact sent only to the
member's registered number. For a member whose WhatsApp is on a different number, the code will not arrive; they can still send the
message, or carry on without WhatsApp.

**5. Not for a member who switched WhatsApp off before.** A member who once had WhatsApp on and took it back (in the app, by STOP, or
through WhatsApp) is not offered a code. To switch it on again they send the short message from their own WhatsApp — the rule you
ratified in July (*"Re-opt-in after revoke requires a NEW inbound message"*), which your 21 October ruling left in place.

**What we did.** Nothing here changes who may say yes or how, beyond what you ruled. Meta must approve the code message before any
Pariwar can use it, and its price is to be recorded from Meta's own rate card first. Counsel has not been asked, as your ruling accepted.
