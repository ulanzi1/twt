# Terraform `terraform plan` expectations — Cloudflare edge module

Reference document — captures the expected resource-add count for the Story 1.13
Cloudflare edge IaC. Cross-reference for BigDev when executing the **deferred** live
zone-onboarding leg (the D-item; analogous to infra/gcp's D1-1.2 / D1-1.5).

**Story 1.13 closure does NOT apply this plan.** There is no live TWT Cloudflare zone
in this environment. The HCL is authored-but-not-applied (the substrate pattern); live
`terraform apply` + zone onboarding is deferred, gated on the §5.8a DPDPA legal-review
(architecture L247-254) recorded OPEN in ADR-0010.

## Story 1.13 — Cloudflare edge substrate

Running `terraform plan` against a real zone with the **default** dev posture
(`enable_bot_management = false`, `enable_logpush = false`, `origin_hostname = null`)
should produce:

```
Plan: 5 to add, 0 to change, 0 to destroy.
```

With the 5 resources being:

1. `cloudflare_zone_settings_override.twt` — TLS-strict + HSTS + baseline security.
2. `cloudflare_ruleset.waf_custom` — per-surface bot-score WAF custom rules.
3. `cloudflare_ruleset.edge_origin_auth[0]` — edge-auth header injection (`header_secret` default).
4. `cloudflare_turnstile_widget.auth` — auth-surface widget (site + secret keys).
5. `cloudflare_turnstile_widget.member_surfaces` — FR-88 member-surface widget.

### Conditionals (additive)

| Variable                              | Adds | Resource(s)                                  |
| ------------------------------------- | ---- | -------------------------------------------- |
| `origin_hostname` set (non-null)      | +2   | `cloudflare_record.apex`, `cloudflare_record.www` (proxied) |
| `enable_bot_management = true`        | +1   | `cloudflare_bot_management.twt[0]` (Enterprise / SBFM) |
| `enable_logpush = true`               | +1   | `cloudflare_logpush_job.edge_logs[0]`        |
| `edge_only_ingress_mechanism != "header_secret"` | -1 | drops `cloudflare_ruleset.edge_origin_auth[0]` (Tunnel / AOP wired GCP-side) |

So the full prod posture (origin + bot-management + logpush, `header_secret`) plans
**8 to add**.

Verification (at the live-apply D-item):

```sh
cd infra/cloudflare
export CLOUDFLARE_API_TOKEN=...
terraform init
terraform plan -out=tfplan-story-1.13
# Resources to add: 5 (dev default) … 8 (full prod posture).
# Resources to change: 0.  Resources to destroy: 0.
```

## Provider-version note

The HCL targets `cloudflare/cloudflare` **v4** (`>= 4.40, < 5.0`) — the schema authored
here. The v5 provider is an API-generated rewrite with breaking resource changes
(`cloudflare_record` → `cloudflare_dns_record`, ruleset `value`/`content` shifts,
zone-settings split). The live-apply D-item MUST re-validate against whatever provider
is current at onboarding and adjust the resource schemas accordingly before applying.
