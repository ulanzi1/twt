## 2. What Went Well

### W-1 — The forward-contract bet paid off, exactly as designed
9.4's headline live-DB test proved a real matcher run flips a seeded member yellow→green at the 8.3 contributor list **and** the 8.6 Yogdaan Bahi green arm **with zero changes to those reads** — because Epic 8 pre-built them to populate the moment the producer emitted the exact frozen names. Epic 8's I-3 lesson (*"a forward seam is inert-until-populated only if the producer emits the exact frozen NAME"*, `[[project_contribution_event_name_contract]]`) was validated live. 9.5 was consequently a `[CONSUMER]`+INVARIANT story, not a rebuild — it explicitly did NOT re-emit or re-implement the flip.

### W-2 — Every Epic-8 critical-path item cleared before/into Epic 9
**AI-8-3 (real per-Pariwar delivery providers) closed 2026-07-25, BEFORE Epic 9 started** — `boot.ts` now wires a real `resolveProviders` (`buildContributionProviderResolver`); a provisioned worker delivers real bytes (push v1 global-credentialed; genuinely per-Pariwar Firebase deferred with a named re-trigger). **AI-8-1 (mismatch-name reconciliation + teeth) discharged in 9.4/9.5** — the matcher emits the EXACT `contribution.reconciliation-mismatch` string and the 9.5 canonical-truth fence enforces single-authority. **AI-6-3-carry-2 (decoy-teeth on 9.x read models) applied** at 9.1/9.12.

### W-3 — The units trap was pre-identified and mechanized, not discovered in production
9.4 named paise-vs-whole-INR (`pools.fixed_amount × 100 === BankStatementEntry.amount`) as *"the single most likely wrong-data bug"* in the story itself and locked it with a frozen-vector real-₹ test. Proactive threat-modelling of the one silent-corruption path in a replay-critical financial engine.

### W-4 — The monotonic-confirmation invariant, three layers deep, with the subtle chain done right
Defense-in-depth: (1) the `(member,alert,entry)` keyed-store claim, (2) an event-level pre-read short-circuit, (3) the append-only events_log immutability trigger — and **no matcher code path emits a reversal** (structural). The reversal event lives in `reconciliation.*` (not `contribution.*`) precisely to keep the 8.10 fence green. 9.5's reversal-consumer got the **per-confirmation-event-id chain** correct (a reversal walks back exactly the confirmation it names; a fresh confirm re-greens) rather than the naive "any reversal → held forever" that would permanently poison a re-confirmed member.

### W-5 — Integrity honesty held a 9th epic
The `A-grief-fursat-cadence` research risk surfaced **un-resolved** (the Story 0.9 bereaved-spouse interview is still `_AWAITING_CONVERSATION_CONDUCT_`) and was never treated as empirically confirmed in any commit or completion note. 9.3 honestly **disabled** its dead resume-link SMS/email UI and **unchecked its own Task 6** rather than ship inert UI as done; ADR-0034's "signed-URL now BUILT" overclaim was corrected to "implemented, no live caller." The sender-VPA match arm ships as a first-class `{available:false}` seam, never a fabricated check.

### W-6 — 3-layer review caught real wrong-data bugs DB-free tests structurally can't
9.4: the same bank-statement entry backing **two** members' confirmations (duplicate/forwarded UTR) — fixed with entry-claim exclusivity across ticks; the timestamp-window secondary check **never actually wired** into the live matcher; a **debit/reversal row with a matching UTR+amount confirming as a deposit** (`entry_type` was dropped from the projection); a pre-commit enqueue violating the POST-COMMIT contract. 9.11: a mismatch-selection order-dependence bug (no `ORDER BY`) fixed to track true max-`occurredAt`. These are the class of defect the review layer exists for.

## 3. What Was Hard / What Leaked

### H-1 (headline) — the danger clustered at Story 9.8, the human-actor money surface → **AI-9-1**
The trustee review-and-reverse queue — the *only* un-confirm path, and the surface that touches money and crosses member boundaries — carried the most severe findings of the epic, all patched in review, none catchable by DB-free unit tests:
- a **cross-member PII leak**: `belongsToMember` returned `true` when `memberId` was `null`, so `takeover`/`manual_transcription` pool-level cases folded in *any other member's* mismatch reasons, self-verify screenshot keys, and confirmed/rejected event ids — and the admin UI rendered the screenshot unconditionally, exposing an unrelated member's evidence to the trustee;
- **no ownership validation** that a client-supplied `reversed_confirmed_event_id` / `bank_statement_entry_id` actually belonged to the loaded case (a wrong/malicious id could reverse a *different* case's confirmation or link the wrong money);
- **no case-status guard**: an already-resolved case could be re-confirmed / re-rejected / re-reversed.

The concentration is the lesson: this is exactly the surface where adversarial review reading the handler and tracing the data-flow is non-optional. → **AI-9-1** (a cross-member-scope + resource-ownership test class as a standing item for money-touching admin-action surfaces).

### H-2 — the gate-scope tax recurred, and Task-8's "gate stays GREEN" was a vacuous claim
9.8's `pool-bound-payment-invariant` `SCAN_DIRS` was never extended to the new reconciliation-review surface (its own `DEFERRED_SCOPE` still lists "Epic 9: reconciliation matcher + contributions record writer" as pending). Task 8's "the gate stays GREEN" proved nothing — the classic AI-5-1 trap (`[[feedback_gate_scope_semantic_coverage]]`, `[[project_access_wrapper_gate_pending_scope]]`). Caught in review; but the per-epic gate-scope discipline keeps needing manual enforcement.

### H-3 — epics.md has drifted materially from the shipped contracts → **AI-9-2**
*Every* Epic 9 story carried a "code contract wins over epics prose" reconciliation: snake_case-vs-camelCase payloads, `contribution.confirmation.reversed` vs `reconciliation.confirmation-reversed`, `mismatch-detected` vs `reconciliation-mismatch`, `packages/parsers` vs `packages/bank-parsers`, `bank_allowlist.yaml` vs `bank-allowlist.yaml`. It worked *only because* each story documented the drift — but the epics doc is now an unreliable spec source, and Epic 10 is a fresh 15-story admin domain that will author against it. → **AI-9-2** (a targeted epics.md reconciliation pass before Epic 10 authoring, adopting the shipped contract names).

### H-4 — trustee attribution isn't durable → **AI-9-3**
9.8's `actor_display` (which State-Trustee walked back a confirmation) is a **response-only** snapshot, never persisted — diverging from the `pool-fixed-amount` precedent (`[[project_admin_display_name_attribution]]`) that persists attestations to a dedicated relational table (keeping `events_log` id-only / non-PII). A first attempt to jam `attestedByDisplay` into the `reconciliation.*` event payload was correctly *reverted* (it would leak a display name into the generic event stream). The proper fix is a dedicated reconciliation-review attestations table — a real schema decision, correctly deferred out of a code-review patch pass. → **AI-9-3** (size + design the attestations table, ride an Epic-10 admin-audit story).

### H-5 — recurring non-elevated taxes (recorded, not elevated)
- **Migration drift** now ~0083 (9.4's `bank_statement_entries`), 9th epic on the 0020 snapshot → **AI-6-4** carry.
- **`.limit(500)` / no-cap read cap-sizing** deferred across 9.5 / 9.7 / 9.8 / 9.10. Note the amplifier: **9.10's pending-match sweep is materially more reachable** than the deadline sweep because it scans `closed` alerts too, which accumulate across the ~20-day reconciliation tail — the "next tick picks them up" alarm text is false for the overflow set. The fix (keyset cursor across all three sweeps) is codebase-wide, not story-local.
- **The sender-VPA secondary-match arm ships dark** (`{available:false}` — no member/sender VPA is collected anywhere). Confirmation rests on UTR + amount + timestamp-window only (a strong match; VPA is defense-in-depth). A dedicated member-VPA-collection story lights it — a named forward seam.
- **ci:local concurrency-oversubscription flake** recurred every single story again (unchanged from Epic 8's H-5) — always a different innocent-by-isolation package; operator-time tax, no false-negative risk.

## 4. Key Insights / Lessons

### I-1 — Epic 9 is the payoff epic: the discipline earned a track record
Epics 7–8 built primitives behind "no live caller yet." Epic 9 fired the biggest of them — the `contribution.confirmed` producer — and the pre-built reads populated with zero changes exactly as promised. The frozen-name-contract + name-teeth discipline (`[[project_contribution_event_name_contract]]`, AI-8-1) is now house style *with evidence*, not a hope. The seam-then-producer-then-consumer split (9.4 emits / 9.5 fences + consumes / 9.8 produces the reversal) is a repeatable shape.

### I-2 — The worst bugs live where a human actor touches money across member boundaries
9.8 proved DB-free unit tests structurally cannot see cross-member data leaks, missing resource-ownership checks, or missing state-guards on write actions — only adversarial review reading the actual handler and tracing the response contract to the render can. The corollary to Epic 6's Drizzle-correlated-subquery retro (`[[project_epic6_drizzle_correlated_subquery_bug]]`): the review layer's value peaks on the highest-stakes surface, and it should be *deliberately intensified* there rather than uniformly applied. AI-9-1 institutionalizes a scope/ownership test class for that surface family.

### I-3 — A replay-critical financial engine goes wrong silently at type/units reconciliation
Pre-identifying the paise-vs-INR trap + a frozen-vector caught the *known* silent-corruption path; the review still found the *unknown* siblings (a debit could confirm as a deposit; a duplicate UTR could double-confirm). The lesson: threat-model the one obvious units/type trap up front AND keep adversarial review for the ones you didn't predict — neither substitutes for the other.

### I-4 — A spec doc drifts silently when the code contract is the real authority
Because the shipped read constants (`CONFIRMED_EVENT_TYPE`, the camelCase keys) were the load-bearing contract, every story correctly coded to them and *documented* the epics.md divergence — but the accumulation means the planning doc no longer describes the system. The discipline that saved each story (code-contract-wins + record-the-reconciliation) is not a substitute for periodically reconciling the source doc back to reality (AI-9-2), especially at an epic boundary into a fresh domain.
