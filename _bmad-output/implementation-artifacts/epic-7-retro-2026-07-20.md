## 1. Epic Summary

Epic 7 is **the math heart of PRD §9.1** — correctness is non-negotiable. At trustee bulk-approval (cycle freeze, delivered by Epic 6's Story 6.13 `pool-spawn-trigger`), the engine atomically spawns N pools (one per approved claim), names them from a culture-rooted curated list (Mahabharata seed), assigns every valid member deterministically via `pool_index = hash(member_id + cycle_id) % N`, snapshots `fixed_amount`, and emits all events — **replay-verifiable, idempotent, partitioned for capacity**. Saga decomposition targets a **< 60s p95 envelope at N=50 / M=4L**.

## 2. What Went Well

### W-1 — The third clean event-derived-state primitive
Pool (7.1) is the third instance of the member 3.1 → claim 6.1 shape: projector-only `current_state`, derived from event replay, guarded by a dedicated DB trigger **and** an AST gate (`pool-state-invariant`, now file+function-scoped after review). The frozen `state-machine.ts` framework transferred intact a third time ([[project_member_lifecycle_domain_substrate]], [[project_pool_primitive_substrate]]). The events↔domain no-cycle constraint was honored (pool homed at `packages/domain/src/pool/`, not a fresh `packages/pool-lifecycle` that would cycle).

### W-2 — Atomicity solved at the right level (7.3)
The load-bearing decision was resolved precisely, dodging both traps: **not** one giant transaction (would destroy the <60s envelope), **not** visible partial state. The resolution — cycle-visibility atomicity gated on the exactly-once `cycle.frozen` event, last-child-finalizes under an advisory lock + the `(stream_id, event_version)` unique index, forward-recovery instead of distributed rollback ([[project_pool_spawn_saga_atomicity]]). Review caught that children weren't actually dispatched concurrently (sequential `for` loop, no worker concurrency) — a defect that would have silently blown the capacity envelope while passing every functional test.

### W-3 — Determinism as replay identity (7.4)
`POOL_ASSIGNMENT_HASH_VERSION` gates the **whole algorithm** — hash function, truncation width, preimage delimiter, **and the balancing rule** — because the balancing pass is replay identity exactly as much as SHA-256 is; a "better" redistribution silently shipped would re-route real members' money for an already-frozen roster. Enforcement is a frozen full-population reference vector, not just the hash. Property tests run at 10 → 50,000 synthetic members ([[project_pool_assignment_engine]], [[project_niyamavali_precedence_is_provenance]]).

## 3. What Was Hard / What Leaked

### H-1 (headline) — The P0 measured-validation number is un-attested
Story 7.9's 4L/N=50 <60s p95 gate is a **Phase-1 launch-blocker**. The harness is built, extracted, and smoke-proven end-to-end against real Postgres — but the actual 4L run is operator-executed and has not happened; the number is honestly carried un-attested (launch-gate Row 13 `conditional`, Decision 2026-07-19-066 *AWAITING EXTERNAL ACTION*). This is the single most important open risk into Phase 1, and un-gated re-commitments decay ([[feedback_record_unattested_no_backfill]]). → **AI-7-3.**

### H-2 — `alert_id` binding for `tr=` is deferred to Epic 8's first live caller

### H-4 — Migration drift continued (~0074, hand-authored on 0020)

## 4. Key Insights / Lessons

### I-1 — The per-epic scope-extension convention's real value is knowing when *not* to extend
Epic 6's AI-6-1 could have been read mechanically as "add every new surface to the access-wrapper gate." Epic 7 read it correctly: the pool engine's defect family is determinism/replay/saga, not caller-fail-closed / secret-compare / compensating-audit — so running the access-wrapper invariants over `pool/` would be **vacuous for the wrong reason** (green, but proving nothing). The convention (README §AI-6-1) explicitly encodes this: coverage is complete only when an invariant has *meaningful semantic coverage*, and you do not run one where it can only be vacuous. Pool got its own two gates instead. This is [[feedback_gate_scope_semantic_coverage]] operating as designed — the gate grew *with* the code, via the *right* gate.

### I-2 — The corrosion risk moved from "build the gate" to "run the measurement"
Six epics of retros hardened *mechanization* into routine (dedicated gates, 3-layer review, Acceptance Auditor, projector-only invariants). Epic 7's exposure is one layer up: the P0 launch gate's tooling is built and honest, but the expensive measurement it exists to demand hasn't been executed. The decay surface is no longer an un-built gate — it's an un-run measurement + the discipline not to fake it. The fix is the same shape as every prior epic: give the re-commitment a gate ([[feedback_record_unattested_no_backfill]]).

### I-3 — "First live caller" is now a recurring seam discipline, not a one-off
AI-5-2 de-risked `dispatch`'s first live caller; 7.3 was `cycle.frozen`'s first live caller (wired the real `PoolSpawnTrigger` from 6.13's bulk-approval); Epic 8's 8.1 will be the first live caller of both `cycle.frozen`-as-consumer *and* the `alert_id`-bound `tr=`. Each time, the seam existed as a primitive for an epic before anything fired it. The lesson holds: confirm the first live caller in a controlled test before trusting the seam in the running surface.
