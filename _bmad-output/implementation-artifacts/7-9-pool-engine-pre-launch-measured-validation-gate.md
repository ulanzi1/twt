## Story

As **Solo Builder + Trustee Panel**,
I want **a pre-launch measured-validation gate that drives the real Pool-Spawn saga at envelope capacity (N=50 pools / M=4L synthetic active-and-valid members in a non-production Pariwar / < 60s p95 wall-clock, ≥ 10 runs) and records `schema_version`-stamped evidence to a committed doc**,
so that **Phase 1 cannot launch without measured proof that the saga decomposition meets the AR-68 / NFR-7 capacity envelope — and if the envelope does not hold, the shortfall is surfaced (predicate materialized) and remediation precedes launch, not discovered in production.**

## Context & Scope (read this first)

This story is `[GOVERNANCE]`. Its deliverable is **not** new engine code and **not** a rendered screen — it is a **measurement harness + committed evidence + a launch-gate disposition**. It executes the capacity claim the whole Pool Engine (Stories 7.1–7.8) has been built against and turns "we believe < 60s" into "we measured p95 = X across 10 runs, here is the git-diffable record."

**The tooling already exists — 7.9 reuses it with ZERO new measurement tooling.** Story AI-6-2 (ratified 2026-07-17, `ai-6-2-shared-measured-validation-framework.md`) stood up ONE shared measured-validation framework at `packages/validity-service/tests/framework/` *precisely so that Story 7.9 reuses the same percentile/evidence/replay core* the carried AI-4-1 / AI-4-2 validity gates use. That framework's `README.md` already documents the exact 7.9 plug-in seam (Seed → Measure → Record → Replay → Register). 7.9 does **not** reinvent `measureP95`, `buildRecord`/`recordEvidence`, or `assertReplayStable`. See [[project_measured_validation_framework]].

## Acceptance Criteria

**AC1 — The measured-validation gate runs the saga at envelope capacity and records p95 evidence (Given Sprint Change Proposal Item 15 + AR-68 + Story 7.3 saga)**

1. A **documented test scenario** instantiates **M = 4L (400,000) synthetic active-and-valid members** in a **non-production Pariwar** (validity `is_valid` at the cycle-freeze `committed_at`, seeded via the real event-log path — never an invented column, never a regenerated migration / `DROP SCHEMA` reset per [[project_live_db_test_gotchas]]) and triggers a **cycle-freeze with N = 50 approved claims**. The harness measures **wall-clock from the post-bulk-approval `CYCLE_SPAWN_PARENT` trigger to the `cycle.frozen` event** appearing on the cycle stream (the finalize commit-point — `pool.finalizeCycleIfComplete`, per [[project_pool_spawn_saga_atomicity]]).
2. **p95 across ≥ 10 runs must be < 60s.** The harness uses `measureP95(op, { iterations: ≥ 10, concurrency, warmup })` from the AI-6-2 framework and asserts `results.p95 < 60_000` (ms). `N`, `M`, `iterations`, `concurrency`, `warmup` are env-overridable (`envInt`), with a scaled-down smoke default for ci:local and the 4L/N=50/≥10 configuration for the `MEASURED_VALIDATION=1` pre-launch run.
3. Results are recorded in **`_bmad-output/research/pool-engine-validation-gate.md`** as `schema_version`-stamped structured records (`buildRecord` → `recordEvidence`), **never a bare number** — `{ metric: 'pool-spawn-saga-wallclock-p95', config: { n: 50, m: 400000, concurrency, iterations, warmup, cryptoAdapter: 'n/a', env, dbVersion }, gitCommit, results: { p50, p95, p99, count }, budgetMs: 60000, pass }` — plus a human-readable scenario write-up and **screenshot / terminal-recording evidence** for the Trustee Panel. The committed doc is written **only** on the `MEASURED_VALIDATION=1` run; the per-PR smoke points `recordEvidence` at a scratch file.

**AC2 — Gate semantics: fail-on-breach, remediation precedes launch (Given the p95 threshold)**

4. **Any p95 ≥ 60s FAILS the gate.** `buildRecord`'s `pass` field is `results.p95 < budgetMs`; the pre-launch harness **asserts** `pass === true` so a breach fails the run loudly (a green run over a doctored ceiling is not the deliverable — the budget is pinned at `60_000`). On breach, the story's disposition path is **Row 13 → `open` + a revision-ADR stub** (spawn-saga decomposition or bulk-write mechanism revision, per the roster closure-criteria + architecture lines 4832–4837), NOT a silent in-place engine tweak inside 7.9.
5. The evidence doc records the run **honestly labelled**: `env` = `pre-launch-4L` for the real 4L run vs `ci-local-smoke` for the scaled-down smoke, and the `dbVersion` (`pgServerVersion`) + `gitCommit` (`gitCommit`) provenance. If the real 4L/real-DB environment is not available at implementation time, the 4L number is **carried un-attested** (documented as pending in the evidence doc + Dev Agent Record) and **never reconstructed or faked** to fabricate a pass ([[feedback_record_unattested_no_backfill]]).

**AC3 — Launch-gate inventory registration + closure linkage (Given Story 0.15 launch-gate inventory + Sprint Change Proposal Item 17)**

6. The gate **appears in the launch-gate inventory** with a **named owner** and **closure criteria** — it already does: **Row 13 `fr-20-pool-spawn-capacity-envelope-conditional`** (owner path: Trustee Panel ratifies elevation, **BigDev** primary support / capacity measurement; closure criteria: p95 < 60s at envelope). 7.9 **supersedes** Row 13 per the roster's supersession-only discipline (prior status preserved in a `<superseded …>` marker), authoring the supersession-ready entry:
   - **Envelope holds (measured p95 < 60s):** author the `closed` supersession entry with `closure_evidence_link` → `_bmad-output/research/pool-engine-validation-gate.md` + a new `.decision-log.md` Decision; the actual `closed` flip is gated on **≥ 2-trustee ratification** at the next monthly review (external action — 7.9 delivers the evidence + the ready entry, not the ratification).
   - **Envelope fails (measured p95 ≥ 60s):** flip Row 13 to `open` (predicate materialized) + author the revision-ADR stub; closure then depends on the revision landing + re-measurement.
7. Once closed, the **closure evidence is linked** — the `closure_evidence_link` resolves to the committed evidence doc + the ratifying Decision, per the roster schema. `target_date` is updated from the `predicate-decision-point` placeholder to the actual measurement-execution event.

**AC4 — Reuse discipline (no new tooling; the AI-6-2 seam is honored)**

8. **No new measurement tooling is written.** The harness imports `measureP95` / `buildRecord` / `recordEvidence` / `assertReplayStable` / `gitCommit` / `pgServerVersion` / `envInt` from the AI-6-2 framework core (grep-verifiable single source — no duplicated percentile/evidence/replay code lands anywhere). The **only** new code is (a) the pool-cohort seeder, (b) the pool measurement harness, (c) the committed evidence doc, (d) the Row 13 supersession + Decision, and (e — RATIFIED Path A, see Dev Notes §Structure) the extraction of the core to `packages/measured-validation` that makes it importable across packages.
9. The evidence doc **co-records a replay attestation**: `assertReplayStable({ replays, perturbed })` over `hashMemberToBucket` / the full assignment map for the seeded cohort — the **full assignment-map deep-equality** across replays **AND** a `cycle_id`-perturbation must change the assignment hash (discrimination), the AI-6-2 stronger-than-hash proof. This **reuses** Story 7.4's assignment functions ([[project_pool_assignment_engine]]); it does not re-implement 7.4's determinism suite (which remains the primary proof).

### Fidelity — measure the decomposition, not pg-boss poll latency

AR-68's envelope is about **saga decomposition** (parent → N child jobs, **no inter-pool serialization**). The property that matters is **concurrent child execution against the DB**. Drive the domain saga functions directly (`planCycleSpawn` → N concurrent `spawnChildPool` → `finalizeCycleIfComplete`) rather than the real pg-boss workers: pg-boss's poll interval (default ~2s) would dominate and *misrepresent* the compute cost of the decomposition. - **`t1`** = the `cycle.frozen` event on the cycle stream (`stream_id = cycle_id`; `packages/domain/src/pool/cycle-events.ts`). Emitted **exactly once** via the advisory lock + the events_log `(stream_id, event_version)` unique index.
