## Story

As Solo Builder,
I want a CI gate enforcing that **every** Niyamavali rule record landing in the registry (Epic 2) carries a `benefit_mechanism: 'pool' | 'reserve'` discriminator and that **v1 rules only ever use `'pool'`**,
so that Durghatana Sahayata's v2/v3 `'reserve'` activation is forward-compatible from day one (rules add WITHOUT re-tagging existing v1 rules), accidentally-untagged rules cannot land, and the FR-100 forward-compat-hooks discipline (architecture §1.13 **Hook 1**) is discharged continuously across every intermediate epic — the closing fourth gate of the Epic 1 governance CI-gate cluster (1.16a friction-budget · 1.16b pii-scrape · 1.16c schema-diff · **1.16d benefit_mechanism**).

### AC-2 — Verification engine: rule-record tag scanner + enum-definition cross-check + schema-column check (pure, fixture-tested)
**Given** the config (AC-1) + the three artifact domains the epics AC enumerates ("rule fixtures, migrations, and seed data", epics L1356) + the registry shape (Story 2.3: `clause_versions.benefit_mechanism` enum NOT NULL, L1452)
**When** the gate evaluates the repo
**Then** it runs **three pure checks**, each fixture-unit-tested with a **positive** (violation → finding, asserting the named pointer) **and** a **negative** (compliant → no finding):
  - **(a) Rule-record tag scan (the core AC — fixtures / seed / migration inserts).** For every rule record extracted from a declared `rule_source`, assert: (i) it **carries** `benefit_mechanism`; (ii) the value is **one of `mechanisms`** (`pool | reserve`); (iii) if `v1_only`, the value is **one of `v1_permitted`** (`pool`). A missing tag, an out-of-enum value, or a `reserve` tag while `v1_only` is a **finding that names the offending rule** (clause id / source file + line). At v1 there are **no rule records** → this check finds nothing (no-op).
  - **(b) Enum-definition cross-check (teeth NOW).** Assert the shipped `BenefitMechanism` enum (AC-1) declares **exactly** the config's `mechanisms` — no drift, no missing `reserve`, no extra value. Implementation: **use a dynamic import** (`await import('../../packages/contracts/src/rules/benefit-mechanism.ts')`) rather than source-text parsing — a `ZodEnum` instance exposes `.options: [string, ...string[]]` which is format-insensitive and cannot drift from the actual runtime type. Compare sorted arrays (`[...enum.options].sort()` vs `[...config.mechanisms].sort()`) so ordering differences in either source are not false positives. This makes the forward-compat type guarantee enforceable and gives the gate a **non-vacuous v1 assertion** (it is green-by-construction *with teeth*, not pure no-op).
  - **(c) Rule-table schema-column check (no-op until Story 2.3).** When a `rule_sources.tables` table appears in the latest drizzle `migrations/meta/*_snapshot.json`, assert it carries a `benefit_mechanism` column (the Story 2.3 NOT-NULL enum). Absent table → no-op.
**And** any finding **fails CI** with a clear pointer (kind + offending rule/artifact + file/line + which rule it violated) — structured `findings[]` accumulation + per-finding print + `process.exit(1)`, mirroring `schema-diff`'s `findings[]` / `friction-budget`'s `failures[]` posture.
**And** all logic is **pure + importable** (takes already-read content / parsed records, returns `Finding[]`): the per-record validator `validateRuleRecord(record, config)` and the orchestrator `validateRuleRecords(records, config)` are exported so **Epic 2's rule seed-loader / registry tests reuse them** (the seam — exactly as 1.16b's engine is imported by the future live-render integration spec). The impure glob/read/exit lives in `check.ts`.
