v4 changes summary

  • Donation ID replaces "#" as the column header (the permanent sequential contribution reference — used internally and surfaced publicly).
  • HRMS column added back to the Sahyog List. Bihar's teachers use HRMS (Human Resource Management System); other states' Pariwars may use eHRMS. The column label is per-Pariwar configurable. HRMS provides government-cross-reference for verification when donor names collide; Member ID remains the canonical TWT-internal lookup.
  • School column added to Yogdaan Bahi — the Late Teacher's school (where the deceased served). Gives the member context about who they supported. Member's own school remains in the page header.
  • Hindi numerals in Panchayat Noticeboard fixed to Latin. Operational stats AND celebration framing both use Latin numerals. Hindi numerals are reserved exclusively for memorial Devanagari prose on the Shradhanjali surface (e.g., "३४ वर्षों की सेवा" embedded in narrative copy). Standalone counts, amounts, and dates always render in Latin.

Numeral handling — tightened rule (v4)

  • Operational surfaces: Latin numerals (dates, counts, amounts, identifiers — all Sahyog List columns, Yogdaan Bahi columns, search inputs, footers, stat strips).
  • Noticeboard surfaces: Latin numerals — even for celebration framing (₹ 45,88,000 / 14,800 / 50,000 all in Latin). Devanagari text in titles and meta lines is preserved.
  • Memorial Devanagari prose only: Hindi numerals permitted when embedded in narrative Hindi copy on the Shradhanjali surface (e.g., "३४ वर्षों की सेवा"). Memorial dates render in Latin ("Born: 1962 · Passed: 2026"); memorial counts and amounts also Latin ("14,800 सहयोगियों", "₹ 45,88,000").

Public column inventory — Sahyog List

Donation ID · Member ID · HRMS · Donor Name · School · District · Block · Pool · Late Teacher · Date. Of these, Member ID and Late Teacher are styled as clickable (canonical lookup + cross-reference to memorial page). Donation ID and HRMS are visible identifiers but not styled as primary actions. Pool renders as letter code only.

Real Data Test — must include mobile per amendment

Before locking visuals: render Sahyog List + Yogdaan Bahi with 300+ real records that exercise the disambiguation surface (duplicate surnames, duplicate full names, long school names, same-day claims across districts, multiple Late Teacher entries with the same surname, HRMS-near-collisions). The test runs on both desktop AND mobile (360px-wide viewport representative of Bihar mid-range Android) under throttled bandwidth and slow-CPU conditions. Approval question: can a user locate a specific contribution in under 10 seconds on the mobile target device? Desktop validation alone is misleading — the surface lives on Sushil's bus commute phone, not on a designer's laptop.

Per-Pariwar column label configurability

The HRMS column is one example of a per-Pariwar configurable surface label. TWT-Bihar renders "HRMS"; a state Pariwar where the local government uses eHRMS renders "eHRMS"; a Rail Parivar might render "PF Number" or "Railway ID"; a Bank Parivar might render "Employee Code". The column semantic is "government-issued service identifier for cross-reference"; the label adapts to the Pariwar's host system.

What this reference does not show

  • Status-mismatch warm-umber tone (specified separately in §8)
  • Reduced-motion / low-bandwidth behavior (not visible in static reference)
  • Larger-touch-mode (44pt → 56pt+ accessibility opt-in not shown)
  • Tier-2 surfaces (Helpline Operator console, Trustee tooling, admin UI primitives — deferred to §10)
  • Full-scale 300+ row rendering (Variation B shows 12 rows; full-scale validation happens at prototype Real Data Test gate)
  • Devanagari typography validation on target devices (browser default Devanagari shaping here; production validation per FM-2 on Snapdragon 4-series Android)
