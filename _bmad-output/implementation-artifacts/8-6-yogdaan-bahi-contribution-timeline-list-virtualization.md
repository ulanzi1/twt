# Story 8.6: Yogdaan Bahi `<ContributionTimeline>` + List Virtualization `[SURFACE]`

## Story

As Sushil at a chai stall opening his Yogdaan Bahi,
I want a visual contribution passbook showing my full contribution history — pool name, cycle, amount, status, date — virtualized so it never lags,
so that I feel proud of my contributions and can show others my Yogdaan Bahi, and I can see my own confirmation status anytime without asking (FR-12A self-visibility).

## Acceptance Criteria

_Elaborated from `epics.md:2961-2977` (Story 8.6) — the epics.md text is 2 short `Then` blocks; expanded here with the read-model source (AC1), the status derivation + the self-view-vs-public distinction (AC2), the Contribution-Note seam (AC3), the virtualization contract (AC4), UX-DR50 save-and-resume (AC5), and the register/numeral/a11y disciplines that bind it (AC6). **AC1 — The passbook lists the member's own contributions, resolved server-side**
**Given** UX-DR27 (`<ContributionTimeline>` Yogdaan Bahi) + FR-12A self-visibility (`ux-design-specification.md:925`)
**When** the Yogdaan Bahi is implemented
**Then** the timeline lists **one row per the member's own attested contribution** — each derived from a `contribution.utr-attested` event the member authored (Story 8.4) — with, per row: **date** (contribution instant, Gregorian), **sahyog / family** (the deceased member's `firstName + lastInitial` whose family the pool supports — PII-shielded, the same subject the My Pool card shows), **pool** (member-facing letter code + curated Mahabharata name when configured), **cycle** reference, **amount** (the snapshotted pool `fixedAmount`), and **status** (AC2). Rows are ordered newest-first. The list is server-authoritative — the client resolves no identity/status/policy (the `member-pool`/`active-contribution` precedent).

**AC2 — Four-state status, honestly derived; a SELF-view, not a public surface**
**And** each row carries a **status** rendered in one of four tones — **yellow** (attested; told-us-you-paid, still verifying), **green** (`पुष्ट` / confirmed by Epic 9 reconciliation), **red** (reconciliation mismatch), **grey** (on record, cycle closed with no reconciliation verdict — a neutral "unreconciled", never a shame/"you missed" state). Status is a **pure derivation** from the events available for that contribution: green iff a `contribution.confirmed` event exists; red iff a mismatch event exists; else yellow while the alert is not `closed`; else grey. Today green/red are **legitimately empty** (Epic 9's producer is unbuilt) and populate with **zero changes** to this read the moment Epic 9 lands (the 8.3 confirmed-read pattern).
**And** because the Yogdaan Bahi is the member's **own self-view** (FR-12A), showing the member's own yellow/green/red/grey here is correct and is **NOT** a violation of the yellow-never-confirmed invariant — that invariant governs **public / aggregate** surfaces (Story 8.3's confirmed-only contributor list, the My Pool progress meter), never a member's private view of their own claims. A CI test pins this boundary: the history read is member-scoped (own `memberId` only) and green derives EXCLUSIVELY from `contribution.confirmed` (a yellow/attested row can never render as green).

**AC3 — Contribution Note PDF link is a seam to Story 8.7 (not built here)**
**And** each row exposes a **link to its Contribution Note PDF** (Story 8.7 — backlog): the affordance renders and navigates toward the Note; the **PDF generator itself is Story 8.7's** and is NOT built in 8.6. Until 8.7 lands the link resolves to the reserved Note route/placeholder (the same "seam, not consumer" discipline 8.3 used for Epic 9) — a green/confirmed row is the natural first Note target, but the affordance is present on every row.

**AC4 — Virtualized to the P0-5 performance contract**
**And** the list is **virtualized** — it opens with **500 test entries at a 60fps target / 30fps minimum on the Story 0.10 canonical entry-level Android**, using tuned `FlatList` (architecture §4.6: FlatList below the P0-5 threshold; the 10k-entry mobile Sahyog view is Epic 11b's FlashList case, NOT this story). **This performance contract is carried un-attested, not ratified**: Story 0.14 (P0-5 native-stack validation) is `done` at the scaffolding level, but its Tasks 8-11 — the actual on-device 500-row measurement matrix and the ratify-or-pivot decision — remain `_AWAITING EXTERNAL ACTION_` (`_bmad-output/research/p0-5-native-stack-validation.md:9,15-16`; `[[feedback_record_unattested_no_backfill]]`). Implement to the tuned-FlatList configuration as the best current evidence, but do NOT report this AC as device-verified without running the actual on-device 500-row scroll measurement — see Testing Standards. The virtualized list **owns its scroll container** — it is never nested inside a parent `ScrollView`/scrolling `YStack` (nesting silently disables virtualization and breaks this AC).

**AC5 — Save-and-resume (UX-DR50)**
**And** UX-DR50 save-and-resume is supported: opening a Contribution Note while scrolling and returning **preserves scroll position + list data** (no refetch flash, no jump to top) — via the MMKV-persisted TanStack Query cache (already wired) + a navigation/list-retention approach that does not remount the list.

**AC6 — Register, numeral discipline, Hindi-first, accessibility**
**Given** the dignified-respectful register (Story 2.2 tone guide) + UX numeral discipline (amendment A2) + the inherited accessibility posture
**When** the timeline copy renders
**Then** it **never** frames contributions as "obligations" or "dues" — the language is "your support" / योगदान, register-appropriate (enforced by Story 1.17 FM-1..FM-14 microcopy lint); **operational columns (date, pool code, amount) render Gregorian + Latin numerals**, the sahyog/family column carries Devanagari names (UX `:1121-1127`); Hindi-first parity holds (`pnpm i18n:check`); each row is a single screen-reader-friendly labelled unit, the status tone is announced (not color-only), and touch targets on the Note link meet the ≥44pt floor.

### D1 — The Yogdaan Bahi is a member's OWN self-view — the yellow-never-confirmed invariant does NOT constrain it

The load-bearing invariant of 8.3/8.4 — *yellow/attested must never appear as confirmed on public/aggregate surfaces* — governs the **public contributor list** and the **progress meter**, because those are other people's / the pool's aggregate truth (`epics.md:2912,2939-2941`). The Yogdaan Bahi is the opposite: it is **Sushil's private view of Sushil's own claims** (FR-12A self-visibility, `ux-design-specification.md:925`; UX `:909` "his Yogdaan Bahi entry … is the always-available record"). Showing his own yellow (attested/pending) and green (`पुष्ट`) and red (mismatch) **is the whole point** — it is his status, visible without asking. So: (a) the read is hard-scoped to the caller's own `memberId` — it NEVER lists another member's contributions; (b) green still derives EXCLUSIVELY from `contribution.confirmed` (a yellow row can never *render* as green — the status precedence is structural); (c) this is a SELF surface, so it is member-session-gated and out of the public/aggregate confirmed-only teeth. State this distinction in the code header — it's the subtle line a reviewer will (correctly) probe.

### D2 — The honest data source: the member's own `contribution.utr-attested` events (one row each); NO projection table

### D3 — Status derivation: pure function, 4 states, honest today

**Today only `yellow` is expected to occur during normal operation.** `deriveContributionStatus` precedence (highest wins): **green** iff a `contribution.confirmed` event exists for (member, pool) — Epic 9's producer, **empty today**; **red** iff a reconciliation-mismatch event exists — Epic 9, **empty today**; else **yellow** while the contribution's alert is not `closed` (attested, still in an open/live cycle — "told us you paid, verifying"); else **grey** (the cycle `closed` and Epic 9 recorded no verdict — a neutral "on record, unreconciled", NOT "you missed" — the dignified register forbids a shame state, AC6). `alert.closed` is emitted exclusively by Story 8.9 (`packages/domain/src/alert/state.ts:20,26`), which is still `backlog` — so **grey is unreachable today**, exactly like green/red. **Grey becomes reachable once Story 8.9 begins closing contribution alerts.
