# Terraform `terraform plan` expectations

Reference document — captures the expected resource-add count for each
substrate Story's IaC delta. Cross-reference for BigDev when executing the
deferred live-provisioning legs (D1-1.2, D1-1.5, Story 1.15).

## Story 1.5 — Cloud KMS substrate

Running `terraform plan` against the existing Story 1.2 dev state with
`var.app_service_account_email` left at its default (`null`) should produce:

```
Plan: 3 to add, 0 to change, 0 to destroy.
```

With the 3 resources being:

1. `google_kms_key_ring.twt_dev` — `twt-dev-keyring` in `asia-south1`.
2. `google_kms_crypto_key.pii_tier_1_kek` — HSM-backed AES-256 KEK.
3. `google_kms_crypto_key.pii_tier_2_hmac` — HSM-backed HMAC-SHA-256 key.

When `var.app_service_account_email` is set (Story 1.15 substantive populate),
the plan adds 2 additional IAM member resources (`google_kms_crypto_key_iam_member`,
one per key — additive semantics):

```
Plan: 5 to add, 0 to change, 0 to destroy.
```

Verification:

```sh
cd infra/gcp
terraform init
terraform plan -out=tfplan-story-1.5
# Resources to add: 3 (or 5 with IAM bindings).
# Resources to change: 0.
# Resources to destroy: 0.
```

**Story 1.5 closure does NOT apply this plan.** Live provisioning is D1-1.5.
