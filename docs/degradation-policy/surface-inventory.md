## Schema (allowed values + forbidden statuses)

**Columns:**

- `surface_name` — canonical name (matches UX §Surface Priority + architecture §3.4 dispatch + epics surface naming where they exist)
- `tier` — `Tier 1 (member-class)` | `Tier 2 (operator)` | `Tier 3 (public)` | `ASM render-mode` (sub-rows under a Tier 1 surface; not standalone)
- `owning_story` — the Story that ships the surface implementation (Story 0.4 ships the **degradation framing** for the surface, NOT the surface itself)
- `default_degradation_stance` — `live` | `gracefully-suspended` | `degraded-mode`
- `user_facing_copy` — short copy block (≤ 180 chars) summarizing what the user sees under the stance; cross-references the relevant `comms-templates/*.md` for the full template body
- `fallback_handler` — role per architecture Cross-Cutting #9 + UX P0-1 (`P0-1-pending` until Story 0.7 closes; then a citation of the P0-1 ledger row). **Story 0.7 author-commit status (2026-05-30):** the substantive `P0-1-pending` placeholders are citation-slot-committed per `docs/fallback-handler-ledger/backfill-log.md`; the substantive textual replacement of `P0-1-pending` with the named role lands at Story 0.7 Task 9 closure (Trustee Panel + Operations Lead naming event)
- `comms_template_cite` — file path under `comms-templates/` (multiple cites permitted when a surface triggers multiple channels)
- `status` — `drafted` | `reviewed-pending-legal-counsel` | `trustee-signed-off` | `fully-ratified`
- `notes` — Story-dependency notes; owning-Story-not-yet-closed citations; substrate-pivot trigger notes

**Allowed-values legend for `default_degradation_stance`:**

- `live` — the surface continues to operate under degraded posture; degradation comms surface in-context (banner / push / WA) but the surface itself is functional. Examples: member signup per PRD §9.1.1; claim processing per §9.1.1 paragraph 4.
- `gracefully-suspended` — the surface returns a documented holding state with the comms template surfaced inline; user-initiated writes are blocked or queued for post-resolution processing. Examples: feature-flag toggles per PRD §9.1.1 ("feature changes pause"); Niyamavali amendment workflow per FR-7 + §9.1.1.
- `degraded-mode` — the surface operates in a reduced-capability mode (e.g., cron-driven read paths continue; live triage queue depth grows; outbound calls deferred). The comms template surfaces as a banner; user-initiated work that would normally trigger an immediate response now carries a "we will respond when staff bandwidth returns" qualifier. Examples: reconciliation review queue (cron continues; manual triage queue grows); Helpline outbound calls (deferred per architecture §3.5).

**Forbidden statuses (framework violations — these state transitions cannot land silently):**

- A row with `trustee-signed-off` MUST cite a `degradation-policy-ledger.md` "Trustee sign-off log" row by date + trustee identity in the Notes column. No silent ratification.
- A row with `fully-ratified` MUST additionally cite a Story 0.13 counsel-return row in the same ledger (the comms templates the surface depends on are individually `legal-counsel-returned`).
- A row's `default_degradation_stance` MUST cite at least one `comms_template_cite` — a surface with NO comms template is a framework gap (the user is left informationless when the surface degrades), not a valid row.
- A row's `fallback_handler` value `P0-1-pending` is a placeholder; once Story 0.7 Task 9 closes (per-loop-node naming event), every row carrying `P0-1-pending` MUST be amended to cite the P0-1 ledger row (the amendment is its own ledger entry per the supersession schema). **Story 0.7 author-commit status (2026-05-30):** citation-slot-committed per `docs/fallback-handler-ledger/backfill-log.md`; substantive textual replacement pending Story 0.7 Task 9 closure (Trustee Panel + Operations Lead naming event).

**Forbidden-removal rule** (inherited from Story 0.3): row removal is FORBIDDEN. Supersession is the only allowed lifecycle exit — when a surface is renamed, retired, or absorbed into another surface, the row is marked `superseded` with a Notes-column citation of the superseding row's location (in this file or in a successor framework).

**"Not addressed" callout** per [[feedback_closure_language_precision]]: "Not addressed" is NOT a valid stance value. If a surface has neither a documented stance nor an explicit deferral with rationale, that is a framework gap — raise as an Open Question, not as a row state.

## Account State Machine render-mode sub-rows (architecture §3.4 "Lifecycle-driven dispatch suppression")

These rows are NOT standalone surfaces — they are render-modes of the existing Tier 1 surfaces. The inventory records the **policy** ("under degraded posture, frozen-state render-modes continue as-architected; no degraded-posture-specific override"); the architectural §3.4 "Lifecycle-driven dispatch suppression" remains authoritative.

| render-mode | architecture authority | degraded-posture interaction | notes |
|---|---|---|---|
| `claim-filed-frozen` | architecture §3.4 + Story 3.1 (member lifecycle state machine) | Push/WA notifications continue to be suppressed per §3.4; degradation comms are NOT additionally suppressed (the bereaved family needs to know what's happening with the system); the public-page banner is visible on any twt.org visit | The frozen-state suppression in §3.4 is a **member-class push** suppression — the public-page banner is NOT a member-class push and is therefore visible |
| `disbursed-frozen-readable` | architecture §3.4 | Read-only render continues; degraded-posture banner overlays; no member-class push (per §3.4 suppression) | Read-only nature preserved; the surface is still informative |
| `disabled-T+90` | architecture §3.4 | Disabled-state render continues with public-page banner overlaid | Disabled members may still encounter the public surfaces (e.g., a visitor lookup); the banner remains visible to them |
| `public-record-∞` | architecture §3.4 | Read-only public surface continues with banner | The In Memoriam + Sahyog Vivran surfaces are the dominant public-record render path; banner per Tier 3 rows |

**Structural property:** the degraded posture does NOT introduce a fifth frozen state (a `degraded-frozen` class). The Account State Machine remains authoritative per §3.4; the degradation framework operates **alongside** it, never as an extension of it. See `README.md` §6 for the structural invariant.
